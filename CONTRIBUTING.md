# Contributing to Multimodal Video Summarizer

Thank you for your interest in contributing to Multimodal Video Summarizer!

We welcome bug fixes, improvements, documentation updates, performance improvements, and new features.

## How to Contribute

### 1. Fork the Repository

Click the **Fork** button on the GitHub repository to create your own copy.

### 2. Clone Your Fork

Clone your fork to your computer:

```bash
git clone https://github.com/kapilmewada74/multimodal-video-summarizer.git
```

Move into the project:

```bash
cd multimodal-video-summarizer
```

### 3. Create a New Branch

Create a separate branch for your changes:

```bash
git checkout -b feature/your-feature-name
```

For example:

```bash
git checkout -b feature/improve-summarization
```

### 4. Make Your Changes

Modify the code, documentation, or other project files.

Please keep changes focused on one feature or bug fix.

### 5. Test Your Changes

Run the project locally and make sure your changes work correctly before submitting them.

### 6. Commit Your Changes

```bash
git add .
git commit -m "Add your feature description"
```

Example:

```bash
git commit -m "Improve video summarization pipeline"
```

### 7. Push Your Branch

```bash
git push origin feature/your-feature-name
```

### 8. Create a Pull Request

Go to your GitHub repository.

GitHub should show an option to create a **Pull Request** from your recently pushed branch.

Describe:

* What you changed
* Why you changed it
* How you tested it
* Any limitations or known issues

Then submit the Pull Request.

## Contribution Guidelines

Please follow these guidelines:

* Write clean and readable Python code.
* Keep functions focused and understandable.
* Test changes before submitting a Pull Request.
* Do not commit `.env` files.
* Do not expose API keys or other secrets.
* Do not commit downloaded videos.
* Do not commit generated transcripts or temporary files.
* Update documentation when necessary.
* Keep Pull Requests focused on a specific change.

## Reporting Bugs

If you find a bug, please open an Issue and provide:

* A clear description of the problem
* Steps to reproduce the problem
* Expected behavior
* Actual behavior
* Relevant error messages
* Python version
* Operating system

## Feature Requests

If you have an idea for a new feature, open an Issue and describe:

* The proposed feature
* Why it would be useful
* How you think it could work

## Pull Request Checklist

Before submitting a Pull Request, make sure:

* [ ] The code works locally.
* [ ] The changes are relevant to the Pull Request.
* [ ] No API keys or secrets are included.
* [ ] No `.env` file is included.
* [ ] No unnecessary generated files are included.
* [ ] Documentation has been updated if necessary.

Thank you for contributing! 🚀
